## 2. Decisions

### P1 — Module numbering, scope, and reuse
New directory `13_phase_dnm/`. Reuses, not duplicates: `09_methylation/pofo_local.py` (nearest-informative-site rephasing with phase-switch flag → `local_rephase_agreement`; fallback parent-of-origin for untagged reads); `05_denovo/sv_read_review.sh` (junction detection by `SA` tag / CIGAR `D ≥ MINBIG`, per-haplotype depth inside vs flanks, het-SNV persistence → SV adapter and two SV features); `02_tiering/tr_outliers.py` (TRGT `AL`/`SD`, spanning-read QC, margin rule → TR adapter and TR candidate generator). GraphTyper's three-way outcome (METHODS §5) is an orthogonal *label* for exonic SVs, never a feature.

### P2 — Phasing stack: keep HiPhase 1.6.0, add orientation, do not re-phase
Read-based phasing stays HiPhase (already run per family; jointly phased small variants, sawfish SVs and TRGT). Chromosome-scale, parent-of-origin-labelled child haplotypes come from **orienting each existing child block** with a Mendelian vote at informative sites (one parent het, other hom): the block is `HAP1_PAT`/`HAP1_MAT` when the majority is ≥ `orient_min_frac` (0.95) with ≥ `orient_min_sites` (20), else `AMBIGUOUS`; dissenting sites are `n_mendel_err` with positions kept.
*Phase-switch errors inside a block* (added after the week-1 fixture showed them): a block whose informative votes run one sign and then the other is not "mixed", it is two correctly phased halves joined by a switch error. `orient.py` segments the position-ordered votes by an exact dynamic programme over run boundaries (`segment_votes`): at most `max_splits` (3) cuts, each of which must raise the total majority count by ≥ `split_min_sites` (2) — so a lone dissenting vote is a genotype error and never splits a block, a run of two at a block edge does. Each segment is then oriented on its own (`min_sites`, `min_frac`), so a switch near a block end gives one oriented segment plus a short `AMBIGUOUS: LOW_SITES` tail, and a switch-and-back gives three segments. A block whose segmentation orients nothing is reported once as `AMBIGUOUS: MIXED_VOTES` — the pedigree-error / sample-swap signature — and counts no switches. The fixture that forced this: a 60-vote block with two paternal votes then 58 maternal (vote fraction 0.967, so it had passed as "clean") whose first 13 kb were mislabelled. Consequence for every downstream lookup: a read's parent-of-origin label is keyed by `(phase_block_id, position)`, not by block id alone. The number of located switches per sample is an M1 QC number to compare with HiPhase's published rate (R6).
*Measured on the two quads (2026-09-12, four children):* 9.9–16.4 k HiPhase blocks each; 1.9–2.2 M informative sites; Mendelian-inconsistent per informative site 0.0006–0.0011; 313–367 switches located per genome (≈ 1 per 8 k phased hets — same order as HiPhase's published 1 per 3.3 k variants, R6); ambiguous block-bp 9.4–10.8 %, of which `MIXED_VOTES` (the pedigree/phasing-problem signature) is only 0.15–0.19 %, the rest short blocks. **Independent check:** at the 18 imprinting control regions, `09_methylation`'s nearest-informative-SNV parent-of-origin calls agree with the oriented segment in 30 of 30 comparable cases (0 discordant). *Second tier:* a segment with 10–19 informative votes is oriented only if unanimous (`small_min_sites`, `small_min_frac`); with a per-site inconsistency rate of ~0.1 %, ten independent errors agreeing is not a realistic failure mode, whereas the realistic one — a mis-phased block — produces mixed votes and stays `AMBIGUOUS`. Recovers ~2.6 % of bp per genome.
*Cohort (33 families, 35 children, same day):* all pass; het-weighted ambiguity is the gated metric because bp-weighting is dominated by a few giant blocks whose coordinates span pericentromeric het deserts (the cohort's largest `MIXED_VOTES` case, 0.92 % of one genome's bp, was one 18 Mb chr1q12 segment with 54 votes). These regions are exactly where M2 must treat the mask as a flag (P5): the phase labels there are least trustworthy, and `dist_block_edge` / `n_informative_1kb` carry that information into every candidate's evidence vector.
*Tradeoffs.* WhatsHap `--ped` (PedMEC) would re-phase all three samples jointly and give longer blocks, but is slow at 22× genome-wide, SNV-only, and would create a second phasing disagreeing with the `HP` tags already on 2.8 M reads/sample. Orientation is one pass over the VCF, keeps one phasing, and its failure mode is measurable (`AMBIGUOUS` rate, `n_mendel_err`). The 18 imprinting-control regions already phased to parent of origin by `09_methylation` are free ground truth for orientation. WhatsHap `--ped` is an M1 QC comparison on 2–3 trios, chr20–22 only.

### P3 — Transmission map and change points (crossover *or* parental switch)
For each parent, inside each *parent* phase block, the child's allele from that parent (known when the child is homozygous — no phasing needed — or a phased heterozygote in an oriented segment) picks which parental haplotype was transmitted: a vote per informative site, segmented with the same change-point DP as P2 (`segment_votes`, isolated run ≥ `xo_min_sites` = 10). Segments carry `transmitted ∈ {HAP1, HAP2, UNRESOLVED}` with typed boundaries `BLOCK_EDGE` / `CHANGE_POINT`.
**A within-block change of transmitted haplotype is either a crossover or a phase-switch error in the parent's read-based phasing, and at the VCF level the two are indistinguishable** — and switches outnumber crossovers roughly ten to one (300–470 located per genome in the children's blocks vs. ~30–45 crossovers per meiosis; the latter an **unverified** textbook figure). So `transmission.py` emits every change as a `CANDIDATE` with its resolution interval (last informative site before, first after), and the read-level step **M1b2** classifies it: reads of the parent spanning the change point whose alleles on both sides agree with the block's `HP` phase support a **crossover** (the parent's phasing is intact there; only the child's inheritance changes); few or no consistent spanning reads mark a **switch error** (HiPhase had no read evidence to bridge). Crossovers falling *between* two parent blocks are invisible, so the per-meiosis crossover count is a lower bound and the fraction of parental hets inside resolved segments is reported next to it. A candidate inside a change-point's resolution interval gets `NEAR_CHANGE_POINT` in M2; the child's own `XP` label does not change at a crossover — only the parent's transmitted haplotype does.
*Measured on 12 simulated trios (2026-09-12):* 0 of 858 resolved segment ends disagree with truth; all 49 change points coincide with a planted crossover or a planted parental switch; 32/48 planted crossovers recovered (the rest between blocks or with < 10 votes on one side); 95.9 % of parental hets resolved.
*M1b2 on real data (first quad, same day):* the read-level test must be **allele concordance**, not spanning-read count — the count version passed 137–179 "crossovers" per meiosis because ≥ 3 tagged 15 kb reads span almost any gap. With concordance (reads spanning two consecutive phased SNV hets whose bases support the same tagged haplotype vs. different ones; intact phase → discordance ≈ 0, switch error → correct reads all discordant): **29–32 paternal and 41–59 maternal crossovers per meiosis** against the known ~26 / ~43 (Halldorsson *et al.* 2019, deCODE — **unverified** here), ratio ~1.6 reproduced. ~85 % of candidates stay `AMBIGUOUS` (gaps longer than a read, or reads that disagree with one another — pericentromeric segdups, chr9 above all) and those loci carry `NEAR_CHANGE_POINT` in M2 rather than a resolution. Child-side switch errors (5.7 % of candidates, 27× chance) are flagged by proximity to the child's segment boundaries, not resolved.
*Cohort (35 meioses per parent, same day, after making the tested span cover the whole change interval):* crossovers per meiosis median **30 paternal / 43 maternal** excluding intervals containing a located child switch (34 / 47 including them), ratio 1.43; switch errors 9 / 7; ~80 % of candidates ambiguous. Maternal matches the deCODE average; paternal is ~15 % high for a method that also misses between-block crossovers — the residual is attributed, with moderate confidence, to unlocated child switches and mismapping-prone regions, and the paper reports **crossover candidates with the child-switch flag**, not a recombination map.

### P4 — Tags, and why M1 does not rewrite BAMs
HiPhase already emits `read_name → haplotag` per block for every read (`phase_haplotags/`). M1 therefore emits, per sample, a **block-level** table — `phase_block_id → {XP: P|M|U}` for the child, `phase_block_id → {XT: T|U|N, segment}` for parents — and M2 resolves any read's parent-of-origin / transmission label by `read_name → phase_block_id → label`. No BAM copy, no 105-BAM pass. `phase-dnm haplotag --export-bam` writes `XP:A`/`XT:A` (SAM local-use range) into a new BAM for IGV only. `HP`/`PS` are never overwritten.

### P5 — Candidates enter unfiltered; the mask is a flag, not a filter
Small variants: every site in the **family joint VCF** where a child is het and both parents hom-ref, any GQ (~25 k per child, 0.2). SVs: every sawfish record where the child carries an allele absent from both parents' GTs. TRs: every TRGT locus where a child allele exceeds both parental alleles by ≥ 1 motif unit (no p99+3 margin; that is tiering, not calling). Every existing candidate list is also ingested and cross-referenced (`source_list`), so rescue/demotion can be reported against the current pipeline (P18). `source_tier` and `mask_overlap` are columns. Rationale: the point of the module is to rescue and reject, and the 338 Mb mask (METHODS §2) is where phase evidence is both most valuable and least reliable — it must be *measured* there. The mask remains a filter for burden analyses.

### P6 — Sib-shared variants are kept
Report §3.5 excludes calls shared by both siblings; here they are kept and flagged `SIB_SHARED` — a variant in both sibs and absent from both parents' genotypes is the parental-mosaic signature. Two quads: illustration, not a truth set (R2).

### P7 — The six-haplotype matrix
Rows `M1 M2 F1 F2 CM CP`. A haplotype is *observed* when `dp ≥ k`; `hap_obs_k` counts over six; k=3 and k=5 are always both computed. At ~11× per haplotype, k=5 is the working threshold in unique sequence; k=3 is a fallback that carries `LOW_HAP_DEPTH`. *Measured (hapdepth, 105 genomes, 2026-09-12):* per-haplotype depth median 10.0× / 10.0×, 88 % of depth haplotagged, but three genomes sit at 8.3–10.0× total (~4 reads per haplotype), where k=5 is mostly unreachable and even k=3 will often fail on one of six rows — for those families `hap_obs` is a property of the sample, not the site, and every M2 table carries the sample's per-haplotype depth so no reader mistakes low observability for evidence (R11). Untagged reads count in `untagged_dp/alt` and in child-level allele support (as the existing DNM logic does) but never in a haplotype row. A read whose `HP` disagrees with `local_rephase_agreement` moves to `amb` and the candidate gets `HP_REPHASE_CONFLICT`. TR rows carry per-read allele-length distributions (from `AL:i` in the spanning-read BAM); "alt" for TR is the expanded child allele (`class_payload.expanded_allele_idx`).

*Clarified 2026-09-13 (thresholds 0.2.0).* **"Observed" means k READABLE reads** — reads that report REF or ALT at the site. A read that is deleted, soft-clipped or carries a third base there (`AMB`) counts towards depth but does not observe the allele; the error allowance `e = max(1, 0.05·n)` and the mosaic depth floors are on readable reads too. Found on the cohort: 4,276 rule-only "phased germline" SNVs (paternal fraction 0.501, i.e. noise; median caller GQ 8) were sites where the transmitted parental haplotype had e.g. 7 reads of which 6 were unreadable and 1 was ALT — depth said observed-and-clean, the reads said unobserved-with-an-alt. Two registry features carry the signal (`c_amb_frac_hapA`, `p_amb_frac_max`, rf_safe) and rows with > 30 % unreadable reads on any haplotype are flagged `AMBIGUOUS_READS`. Because every rule input is a count column of the evidence table, the rule layer can be re-run without the BAMs (`phase-dnm reclassify`, seconds per child); the review output is kept immutable as `*.evidence.review.tsv` and the working `*.evidence.tsv` is its reclassification under the current thresholds version.

### P8 — `phase_class`: rule layer (transparent)
Evaluated in order; first match wins. `T` transmitted parental haplotype, `U` untransmitted, `A` the child's alt-carrying haplotype, `O` the other; `f_A = alt/(alt+ref)` on A; `e` = per-read error allowance (`thresholds.yaml`: max(1 read, 5 %)).

| class | rule |
|---|---|
| `phase_conflict_artifact` | alt > e on **both** child haplotypes, **or** alt > e on ≥ 2 parental haplotypes with no parental het GT |
| `inherited_missed_in_parent` | T observed and alt_T ≥ max(3, 0.3·dp_T) |
| `parental_mosaic_transmitted` | T observed, e < alt_T < 0.3·dp_T, `dp_T ≥ mosaic_min_dp` (P10); else `inconclusive` + `PARENTAL_ALT_LOW_DEPTH` |
| `child_postzygotic_mosaic` | alt confined to A, `f_A ≤ 0.7`, `dp_A ≥ mosaic_min_dp`, alt_O ≤ e, all four parental haplotypes observed with alt ≤ e |
| `germline_DNM_phased` | alt confined to A, `f_A ≥ 0.8`, alt_O ≤ e, T observed with alt_T ≤ e, U observed |
| `germline_DNM_unphased` | alt confined to A (or child unphased with AB 0.25–0.75), parental alt ≤ e on every *observed* haplotype, but `hap_obs_k5 < 6` or T unresolved |
| `inconclusive` | everything else, with a reason flag |

`rule_score` = number of satisfied germline criteria (0–6). All thresholds live in `thresholds.yaml` with a version string written into every output row. An evidence floor applies before any germline or mosaic class: `min_alt_reads` (3) alt reads in the child (first cohort run without it made single-read "germline" calls), and `germline_DNM_phased` requires all four parental haplotypes observed and alt-free, not only the transmitted one.
*Measured on the raw candidate set, 34 children (2026-09-12):* per child, SNV `germline_DNM_phased` median 192, `germline_DNM_unphased` 1,568, `inherited_missed_in_parent` 398, `phase_conflict_artifact` 1,853; INDEL phased 783 / inherited-missed 2,316 / conflict 5,706; SV phased 7; TR phased 938 / conflict 17,333. **Parent of origin among `germline_DNM_phased` SNVs: paternal fraction 0.571 (95 % CI 0.559–0.583) overall and 0.668 (0.650–0.685) at child GQ ≥ 20** — the signature of a class mixing real DNMs (~0.77 paternal) with artefacts (0.50), real share rising with quality; a two-component estimate gives ~50 real phased SNV DNMs per child by either route, in line with the phased half of ~60–70. INDEL (0.511) and TR (0.511) phased-germline sets are artefact-dominated as expected for homopolymer errors and stutter; SV 0.598 on 251 events. Conclusion for the design: **the rule layer enriches but does not purify the raw set** — as intended, the classifier (P11) carries the quality signal and the phase layer carries the transmission test; a rule-layer call alone is never a DNM call (P15, R4).

### P9 — Likelihood layer
Per-haplotype alt/ref counts are binomial with hypothesis-specific expected alt fractions, H ∈ {germline DNM on A; inherited from T; parental mosaic on T at fraction m; child postzygotic on A at fraction c; artefact at rate ε on all six}. ε per class from cohort hom-ref sites in the same mask/mappability stratum; m, c integrated over Uniform(0.02, 0.5). Priors from expected rates vs. the measured candidate counts (0.2). Output: posterior per hypothesis; `lik_post_germline` is `phase_score`. Both layers always emitted.
*Implemented 2026-09-13* (`classify/likelihood.py`; runs as a post-step over evidence tables using the orientation and transmission columns; unresolved transmission treated as an unordered pair; `lik_log10lr_germline` is reported against the *best alternative*, named in `lik_best_alternative`). Two properties fixed by the tests and worth stating in Methods: (i) at ~10 reads on the transmitted haplotype the nearest alternative to a clean germline pattern is a **low-fraction parental mosaic**, not an artefact — posterior ~0.98 and log10 LR ~0.8, rising with depth (0.99 / 1.1 at 20 reads) — so the LR is depth-limited at cohort coverage and the mosaic prior (a minority of apparent DNMs, ~10⁻⁴ per candidate; unverified) matters there (P10); (ii) two alt reads on an otherwise clean matrix still score ~0.7 — the posterior is a statement about hypotheses, not an evidence floor; the floor (`min_alt_reads`) lives in the rule layer and P15 uses both. *Cohort comparison 2026-09-13 (35 children, phased SNVs with a resolved parent of origin):* rule `germline_DNM_phased` 6,400 rows at paternal fraction 0.571; `phase_score ≥ 0.9` 9,521 at 0.556; **their intersection 2,124 (median 59 per child) at 0.713 (GQ ≥ 20: 0.762)**, while rule-only (0.501) and likelihood-only (0.511) carry no parent-of-origin signal. The two layers fail in disjoint ways — the rule on unreadable reads counted as depth (fixed in P7), the likelihood on unobservability (a haplotype with 0 readable reads leaves the prior to decide, and the prior says *inherited*) — which is the empirical case for P15 using both: rule observability gates, posterior ranks. *After the P7 fix (reclassified cohort, same day):* rule phased-germline SNVs 2,747 at paternal 0.664 (0.746 at GQ ≥ 20), median posterior 0.976, 75 % inside the likelihood ≥ 0.9 set; rule-only shrank from 4,276 to 690 rows.

### P10 — Mosaic evidence floor (overclaim guard)
A mosaic label requires ≥ `mosaic_min_dp` (15) reads on the relevant haplotype **and** ≥ 3 minority-allele reads **and** those reads pass MAPQ ≥ 20, not soft-clipped at the site, NM within the haplotype's ref-read distribution. Otherwise `inconclusive` + `MOSAIC_UNDERPOWERED`. At ~11× per haplotype, f_A 1.0 vs 0.8 is two reads. Mosaics from this cohort are reported as *candidates with read counts*, never as a rate, unless confirmed by targeted deep sequencing (R1).

*Measured by spike-in 2026-09-13 (smoke, one family, ~10 reads per haplotype):* germline and inherited-missed spike-ins of every class recover class and parent of origin at 1.0; child mosaics at 15–30 % and transmitted parental mosaics at 10–25 % do not — they fall to `TOO_FEW_ALT_READS` / `MOSAIC_UNDERPOWERED` / `PARENTAL_ALT_LOW_DEPTH`, or pass as germline (m = 0.10: 0–1 alt reads on T) or as inherited (m = 0.25: 3–4 alt reads of ~10). The depth floor is therefore a property of the data, not of the rule set, and the paper states mosaic sensitivity from the cohort-wide spike-in table rather than claiming mosaic calls.

### P11 — `rf_safe` policy and positive-generation schemes
**P11a (classic swap, primary).** A synthetic trio has real surrogate parents with real haplotagged reads; what is missing is only the transmitted/untransmitted label. A feature is `rf_safe: true` iff computable from (child evidence) ∪ (parent evidence symmetric under swapping the parent's two haplotypes and under swapping the two parents). `features/registry.py` refuses to build an RF matrix with `rf_safe: false` columns; the check hash goes into the manifest. Transmission-dependent features live in P8/P9 only, applied after the RF.
*Clarification (JS asked 2026-09-12 whether "transmitted" is labelled in the swap):* **it is not, and cannot be.** A synthetic trio has no meiosis connecting child and surrogate parents, so "the parental haplotype the child inherited" does not exist for positives; any transmission-dependent quantity would be defined for negatives only and the classifier would learn the definedness, not the biology. The transmitted-haplotype test therefore exists only in real trios (M1 transmission map) and only in the post-RF layer. **Rule (JS, same day): parent-of-origin inference is done in real trios only, and the classifier never sees parent of origin or transmission — not even as a selector of which parent to look at.** (A parent-of-origin-selected parental feature was briefly proposed: the child's label is computed once with the real parents and would survive re-pairing, but in a synthetic trio "the parent of origin" is an unrelated adult, so the feature would mean different things in positives and negatives despite being computed identically. Withdrawn.) The swap trains a de novo *caller*; parent of origin is an M2 *inference* on real trios. Concretely: child-side RF features use the child's two haplotypes sorted so the alt-carrying one is first, never labelled paternal/maternal; parent-side RF features are symmetric over both parents and both haplotypes; `parent_of_origin`, `t_*`, `u_*`, `nt_parent_*`, `dist_crossover` and `sib_shared` are `rf_safe: false` and are computed for every row of the final tables after scoring.
A second asymmetry for Methods: in positives the child variant is truly present (inherited); in negatives most child calls are artefacts. The RF learns largely "is the child genotype real"; only P8/P9 test "is it absent from the transmitted haplotype". Hence the combined final rule (P15).
**P11b (haplotype swap, ablation; Q13).** For a variant inherited on T, delete the alt-bearing reads on T in the parent (downsampling U to keep the T:U ratio); the transmission map survives. Guard: a *chimera test* — a classifier on read-level features alone must not distinguish edited from unedited parental windows; if it does, P11b is reported as leaky.

### P12 — Folds are closed under the swap; pairings are drawn inside folds
Because `swap_pedigree.py` exchanges offspring between paired families, the unit that must not cross a fold boundary is the **pair**. Adopted: fold over families first (all members of a quad together), then draw pairings *within* each fold. With 33 complete-trio children and 5 outer folds: 6–7 families → 3 pairs per fold (+ one unpaired family contributing negatives only, or paired in a second within-fold seed). Extra seeds only within-fold. Inner folds built identically from outer-training families. Stratify by variant class (separate models per class by default; pooled model with class feature as ablation) and by DNA source (saliva vs blood; the REACH quad is the only blood family, so it must not be alone in a fold).

### P13 — The negative set is the raw putative set (measured)
From 0.2: raw negatives ≈ 25 k/child, true DNMs ≈ 70 → ~0.3 % contamination; the SynthDNM assumption holds on HiFi **only** for the raw set. Negatives are therefore the P5 unfiltered candidates. `cv_report.json` reports `negative_contamination_estimate` per class. Iterative relabelling (dropping negatives that a fold-external model calls DNM) runs as an ablation and is labelled partially circular wherever it appears.

### P14 — Metrics, calibration, baselines
**What is trained on what (JS asked 2026-09-12).** Module 1 (phasing) trains nothing: orientation and transmission are Mendelian inference done independently in each trio, so running two quads and then all 33 families was a smoke test followed by the cohort run. In Module 4 the classifier is trained on the **entire cohort**: cross-validation splits the *families* into ~5 outer folds (6–7 each); each fold's model trains on the other ~27 families and is scored on the held-out ones, so every family is scored exactly once by a model that never saw it, and the pooled held-out scores are the performance estimate (P22). **The three shipped models are then refit on all 33 families** with the inner-loop-selected hyperparameters and frozen with a training manifest (P21); the CV numbers describe those models' expected generalisation. Folds are by family (each swap pair inside one fold, P12) because a child appears as the offspring of both its real trio (negatives) and a synthetic trio (positives) and shares inherited variants with a sibling — a random row split, which is what SynthDNM's current `train.py` does, would put a child's variants on both sides and inflate the AUC.
Outer folds: PR-AUC, ROC-AUC, Brier, reliability curves; isotonic calibration fitted on inner out-of-sample predictions. Repeated nested CV (≥ 5 outer-fold seeds) — 33 trios give ~6 families per fold; report mean ± range. Baselines on identical folds: XGBoost without phase features; phase features only; RF; logistic regression; SynthDNM *universal* 21-feature model as published. Permutation importance on outer held-out folds, grouped by feature family. Headline performance on external sets (WES-confirmed exonic DNMs, GraphTyper-confirmed exonic SVs, GIAB), never on synthetic held-out labels alone.

*Attribution plan (JS asked 2026-09-12 how much weight the classifier gives phase; fixed here before any model exists):*
(1) **Ablation on identical folds** — full vs. no-phase vs. phase-only; the reportable statement is on the external sets (recall of WES-confirmed exonic DNMs at fixed FDR, rescued/demoted counts), not the synthetic AUC. (2) **Grouped permutation importance** on outer held-out folds, permuting each feature family (A caller, B context, C reads, D phase) jointly — single-feature permutation is masked by correlated stand-ins. (3) **TreeSHAP** (XGBoost `pred_contribs`, exact, no extra dependency): |SHAP| summed by family gives the share of each decision attributable to phase, cohort-wide and per call — the per-call view is the figure for rescued and demoted calls. (4) Gain importance as SynthDNM already writes it: reported, not relied on. Two caveats travel with every number: the RF's phase importance **undercounts** phase, because the transmitted-haplotype test is `rf_safe: false` and lives in the M2 layer (report both); and a high phase importance can be **leakage** — a phase-only model that performs on synthetic held-out labels but not on the validated external set is leaking, and that check is mandatory before any importance is published. Prior expectation, stated in advance: child-side `c_alt_hap_frac` / `c_alt_confined` will rank high partly because they separate real heterozygotes from artefacts, which is most of what the classifier learns. *Measured (seed-0 fold models, TreeSHAP share on held-out real rows, 2026-09-13):* phase = 0.17 for SNV/indel (caller 0.74, context 0.09), 0.29 for SV (caller 0.68), **0.68 for TR** (caller 0.18, context 0.14); on the rows the classifier itself calls, 0.21 / 0.25 / 0.57. The prior expectation held: `p_max_alt_hap_frac` (a parental-haplotype alt fraction, unlabelled) is the leading phase feature in every class, and `site_qual` + the PL block lead the small-variant model.

### P17 — Adapter inputs come from the WDL outputs that already exist
- **SNV/indel**: pysam pileup at the site in the three haplotagged BAMs; `HP` from the read, cross-checked against `phase_haplotags`.
- **SV**: alt-supporting read names from `sv_supporting_reads.json.gz` (sawfish `--report-supporting-reads`), joined to `phase_haplotags` by read name for haplotype; *plus* the `sv_read_review.sh` junction scan around both breakpoints in **all three** BAMs, because sawfish's per-sample list is at sawfish's own sensitivity and a hom-ref parent's 1–2 junction reads (the parental-mosaic evidence) must be counted independently. Per-haplotype depth inside vs flanks from `hapdepth`.
- **TR**: per-read repeat length from `trgt_spanning_reads/*.bam` (already `HP`-tagged), so the per-haplotype allele-length distribution is a direct read of tags; no re-genotyping. *Tag semantics, measured on 4,385 reads at 300 loci (2026-09-12):* the per-read repeat length is **`query_length − FL[0] − FL[1]`** (TRGT trims each spanning read to the repeat plus the two flanks in `FL`), equal to the sample's called `AL` within ±2 bp in 98.4 % of reads; **`AL:i` on a read is the allele *index* it was assigned to (0/1), not a length**; `SO`/`EO` are the read's offsets relative to the repeat; `TR:Z` is the locus id and is used to drop reads of overlapping loci. Child reads: ALT if within tolerance of the outlier allele; parent reads: ALT if within tolerance of the *child's* outlier allele and not of the parent's own alleles (missed inheritance / parental mosaic), REF if matching the parent's own allele.
Rationale: three adapters, one join key (`read_name`), no new callers.

### P21 — Deliverable: three frozen classifiers, one per class, plus the retraining recipe (JS, 2026-09-12)
The pipeline ships **three** pre-trained models — SNV/indel (one model, `indel_flag` a feature, as in SynthDNM), SV, TR — each with its calibration, class-specific threshold and training manifest (P14, P15), not one pooled model; the pooled model with class as a feature is an ablation only (P12). Reasons: the feature vectors differ by class (sawfish and TRGT fields exist only for their class), the operating threshold is set per class on outer folds, and the class imbalance (tens of thousands of SNV/indel candidates vs. single-digit true de novo SVs cohort-wide, R3) would let a pooled model be driven by small variants. A pre-trained model transfers only to the same callers and versions at similar coverage (DeepVariant + GLnexus 1.4.3, sawfish 2.2.1, TRGT 5.0.0, ~22–24×) — SynthDNM's premise is retraining per pipeline — so the release is the three frozen models **and** the swap-closed, family-grouped retraining workflow for anyone whose callers differ. *Frozen 2026-09-14:* `models/{snv_indel,sv,tr}.xgb.json` + training manifests in the repository (sha256 08537e17… / 178b1f12… / 92244644…; 55 / 38 / 41 features; XGBoost 3.2.0; refit on all 35 children after five-seed nested CV on the re-reviewed tables, `harness_v2`), operating points in thresholds.yaml 0.3.0, record in `models/FROZEN.md`; `phase-dnm score` is the transfer path (frozen model → rf_q against the scored cohort's own candidates → `integrate` unchanged), with the checksum verified against the manifest.

### P22 — Headline result: per-class classifier AUC vs. the original pipeline's heuristics, on one harness (JS, 2026-09-12)
**The question.** For each class — SNV/indel, SV, TR — what is the performance (ROC AUC, with PR-AUC and calibration alongside) of the phase-aware classifier, and how does it compare with the heuristic filters the original pipeline used? Both arms are evaluated by the **same harness** (`src/phase_dnm/eval/`): same candidate sets, same swap-closed family-grouped outer folds (P12), same external truth, same reporting.

**Label sets, in order of weight.** (1) *Primary, SynthDNM construction:* positives = synthetic DNMs from within-fold pedigree swaps, negatives = the raw putative-DNM set of real trios (P5/P13), scored on outer folds; repeated with ≥ 5 fold seeds → AUC mean ± range per class. (2) *External truth:* SPARK iWES v3 DeepVariant genotypes for exonic SNV/indel candidates (101/105 samples), GraphTyper on WES CRAMs for exonic SV candidates, spike-ins for all classes (TR has no orthogonal comparator) — recall at fixed FDR. (3) *Sanity:* per-proband rate against the expected ~60–80 (unverified figure), parent-of-origin ratio on the phased subset, sib-shared calls.

**Heuristic arms, reproduced verbatim from the repo** (each implemented in `eval/heuristics.py` as a scorer returning `pass` — the pipeline's actual decision — and a continuous `sweep_score` obtained by sweeping the rule's natural knob with all other criteria fixed, so the heuristic has both an operating point and a curve; the curve is labelled a *sweep*, never "the pipeline"):
- **SNV/indel — H1 slivar raw** (`01_qc/family_downstream.sb`): child het, both parents hom-ref, GQ ≥ 20 and DP ≥ 10 in all three, child AB 0.25–0.75, parental AD[1] = 0; knob = GQ. **H2 hiconf** = H1 ∩ outside the segdup/repeat mask ∩ gnomAD AF < 0.001. **H3 cohort** = H2 ∩ PON leave-one-family-out ∩ not sib-shared (`03_panel/apply_pon_loo.sb`, `05_denovo/denovo_tier.py`).
- **SV — H1 genotype rule** (`family_downstream.sb`): child GT ∈ {0/1, 1/0, 1/1}, both parents 0/0, no quality filter; knob = child GQ. **H2 cohort** (`denovo_sv_priority.sb`): fractional mask (≥ 50 % of the interval), founder-panel recurrence by reciprocal overlap ≥ 0.5 (flag at AC ≥ 6), cross-family identical-interval flag. Coding-impact prioritisation and GraphTyper are *not* part of the arm — the first is interpretation, the second is truth.
- **TR — H1 per-family** (`family_downstream.sb`): child's longest allele ≥ longest parental + 50 bp and ≥ 1.5× (any uncalled member → not evaluable); knob = gain_bp. **H2 cohort** (`02_tiering/tr_outliers.py`): SD ≥ 5 on every allele, child allele > max(parents) + max(6 bp, k × shortest motif) and > founder maximum, founder reference leave-one-family-out.

**Provenance of the heuristic arms (for the report; verified = checked against the publisher's record 2026-09-12).**
- slivar and its trio de novo expression: Pedersen BS, Brown JM, Dashnow H, *et al.* Effective variant filtering and expected candidate variant yield in studies of rare human disease. *npj Genomic Medicine* 2021;6:60, doi:10.1038/s41525-021-00227-3 — **verified**. Our expression is the documented slivar de novo pattern with the lab's thresholds (GQ ≥ 20, DP ≥ 10, AB 0.25–0.75 — the same genotype QC as METHODS §2 — plus parental AD[1] = 0, i.e. no alternate read in either parent, a long-standing DNM-pipeline convention with no single source).
- The mask (genomicSuperDups + simpleRepeat + RepeatMasker simple/low-complexity), gnomAD AF < 0.001 and the 65-founder panel of normals with leave-one-family-out: lab decisions D56, D60–D63 in the cohort `DECISIONS.md`; gnomAD v4.1 as the frequency source (METHODS §4). No external methods source for the specific thresholds.
- SV genotype rule (child carries, both parents 0/0): the Mendelian definition of a de novo call, no external source. Matching by reciprocal overlap ≥ 0.5 and fractional masking ≥ 50 %: D61–D63 (JS). sawfish 2.2.1 as the caller: PacBio; publication **unverified** here. GraphTyper re-genotyping (used as truth, not as an arm): GraphTyper 2.7.2, Eggertsson *et al.*, *Nature Communications* 2019 — **unverified** here.
- TR per-family rule (≥ 50 bp and ≥ 1.5× the longest parental allele): ad hoc, from the first per-family session; no external source. TR cohort rule (founder p99 + margin, > founder maximum, SD ≥ 5): the outlier-against-a-reference-population idea as in STRetch (Dashnow *et al.*, *Genome Biology* 2018 — **unverified** here) and ExpansionHunter Denovo, with thresholds set in the lab (D55, D59). TRGT itself: Dolzhenko E, English A, *et al.* Characterization and visualization of tandem repeats at genome scale. *Nature Biotechnology* 2024, doi:10.1038/s41587-023-02057-3 — **verified**. PacBio's own `trgt-denovo` trio caller exists and should be cited and, if practical, run as a fifth TR arm — **unverified** here.
- SynthDNM (the classifier family being extended): Lian *et al.* 2021 — verified (§0).

**Four arms per class, one figure each:** H (heuristic operating points H1/H2/H3 marked on the ROC and PR axes), H+P (heuristic followed by the M2 phase rule layer — isolates what phase adds *without* a classifier), RF (classifier alone), RF+P (P15 final). Reported per class: ROC AUC and PR-AUC of RF and of the heuristic sweep; the classifier's sensitivity at each heuristic operating point's FPR and the heuristic's sensitivity at the classifier's chosen FPR; calibration; counts of positives and negatives per fold.

**Fairness rules.** (i) Same candidate universe for every arm: the P5 unfiltered set. (ii) Population/artefact filters (gnomAD, mask, PON-LOO, cross-family recurrence) are information both arms may use — H uses them as filters, RF as features (`B_context`) — so every comparison is reported **with and without** that layer (2 × 2). In synthetic trios the PON leave-one-out removes *both* the child's family and the surrogate parents' family. (iii) Synthetic positives go through each heuristic exactly as negatives do: the slivar expression is evaluated on the swapped trio's genotypes from the joint BCF; sib-shared exclusion is applied to synthetic quads the same way. (iv) Sex chromosomes as SynthDNM handles them (`haploid_flag`, PAR BED). (v) The heuristics are deterministic and untrained, so they have no fold leakage — but they are still scored fold-by-fold so every number sits on identical test sets.

**Mask-stratified evaluation (JS, 2026-09-12).** The original pipeline's region mask (genomicSuperDups + simpleRepeat + RepeatMasker simple/low-complexity, 338 Mb ≈ 11 % of the genome, including the pericentromeric regions inside it) removes every candidate it touches, so any real event there is a false negative *by construction* for the heuristic arm, and its recall inside the mask cannot be measured with cohort data at all. Therefore: (i) every arm's recall and FDR are reported **inside vs. outside the lab mask** separately, and additionally by the GIAB genomic stratifications (segmental duplications, low-mappability, tandem repeats, GC extremes — Dwarshuis *et al.*, *Nat Commun* 2024; **unverified** citation details); (ii) **HG002's Q100 assembly-based benchmark is the only truth that reaches inside the mask** — mapping-based truths (v4.2.1, WES) are blind exactly where the mask is — so the in-mask genotyping/phasing recall of the six-haplotype extractor is measured against Q100 on HG002, and the in-mask *DNM* statement rests on spike-ins planted on haplotagged reads inside masked regions plus the de facto HG002 DNM set; (iii) the module keeps masked candidates with `mask_overlap = 1` (P5), so the cell "inside the mask, classifier + phase" is where the method's added value is either demonstrated or not. Expectation in advance: recall inside the mask is lower for every arm (raw SNV candidates already show a median tagged depth of 7 and `hap_obs_k5 = 0` in 42 % there) but non-zero, against the heuristic's zero.

**Expectations stated in advance, and what would change them.** On synthetic labels the AUC will be near ceiling for the classifier (SynthDNM published 0.997) and may be close for the GQ sweep of the slivar arm — a small AUC gap is the expected result, not a failure. The discriminating comparisons are (a) the operating point on *real* candidates — the original pipeline calls a median of 38 SNV/indel DNMs per proband against an expected ~70 — with the parent-of-origin ratio as the guard against buying sensitivity with artefacts (R9), and (b) external truth. SV and TR positives are scarce (private inherited SVs and private long alleles, pooled cohort-wide): counts and confidence intervals are reported, and per-class thresholds for SV/TR are labelled provisional (R3). If the RF's AUC gain over the heuristic sweep is driven by `B_context` features, the 2 × 2 will show it; if it is driven by phase, the P14 attribution will.

### P23 — Synthetic trios run through the SAME chain as real trios (M4, 2026-09-13)
A synthetic trio (P12: the child of family A with the parents of family B, pairs drawn inside an outer fold) is not a
relabelling of existing rows: its candidate set is regenerated from the cohort-wide joint callsets (`freeze1.cohort.bcf`,
`.sv.vcf.gz`, `.trgt.vcf.gz` carry all 105 samples, so any trio can be extracted), then reviewed against the child's
haplotagged reads and the surrogate parents' reads with **no label tables** (parent of origin and transmission are
undefined — exactly the columns the classifier never sees, P11), then passed through the same feature extractor. Positives
are therefore scored by the same code path as negatives, with the same six-haplotype counts; only the D-block's
rf_safe part (child rows sorted alt-first, parental rows symmetrised) is defined for both, which is the P11 symmetry
argument made operational. Positives are subsampled per synthetic child and class (default 3,000 SNV/indel, all SV, 3,000
TR) because a child against unrelated parents shows ~1.5 M "de novo" small variants — SynthDNM does the same. The
review on synthetic trios is the only BAM pass in M4 (~30–60 min per synthetic trio; one per real child per seed).

### P24 — What the classifier sees, and the labels (M4)
Training rows are the `rf_safe` matrix columns only (registry gate, P11), identical for synthetic and real rows; the
label is 1 for a synthetic-trio candidate and 0 for a real-trio raw candidate (P13). No parent-of-origin, transmitted
haplotype or orientation column is available to any model — JS 2026-09-12: "inferring parent of origin is something we
only do in REAL trios". The phase layer's rf_safe features (`c_alt_hap_frac`, `c_alt_confined`, `hap_obs_k*`,
`p_max_alt_any_hap`, `p_n_haps_with_alt`, `c_amb_frac_hapA`, …) are what "phase information" means in the attribution
(P14). Models: XGBoost (SynthDNM's current backend) per class, RF and logistic regression as baselines on identical
folds; isotonic calibration on inner out-of-sample predictions. **Presence-leak guard (2026-09-13):** the matrix loader drops any feature whose non-missing fraction differs by more than 0.5 between synthetic and real rows, or that is present in fewer than 1 % of real rows, and logs the drop — a column that exists for one label class only encodes the label through its missingness (found when the D block gained read-quality columns between the real and the synthetic reviews). Rule: real and synthetic reviews are produced by the same code revision. Backend versions recorded in `training_manifest.json`
(xgboost 3.2.0, scikit-learn 1.9.1 installed in the module env 2026-09-13).

### P25 — The heuristic arms as scorers (M4, implements P22)
`eval/heuristics.py` implements each arm as a function of the rows the module already has — candidate fields (GT, GQ,
DP, AD, AB) for H1 and the annotation columns (mask, gnomAD AF, PON leave-one-out, sib-shared) for H2/H3 — returning
`pass` (the pipeline's decision, verbatim thresholds) and `sweep_score` (the rule's natural knob with everything else
fixed: GQ for the slivar rule and the SV genotype rule, gain in bp/units for TR). The knob's *direction* is chosen so a
higher score means "more de novo-like"; rows failing any fixed criterion get a score below every passing row, so the
sweep curve's operating point is the pipeline's actual decision. This makes the heuristic an ROC curve on the same folds
and the same rows as the classifier without ever pretending the pipeline produced probabilities.

### P26 — Cohort annotation is leave-one-FAMILY-out and symmetric between real and synthetic rows (M4, 2026-09-13)
The cohort features (`cohort_AC_loo`, `pon_founder_recurrence_loo`, and the H2/H3 heuristic arms that use the panel of
normals) are computed from the 65 unaffected founders' genotypes at the candidate sites (cohort BCF / SV VCF), excluding
the founders of the CHILD's family **and** of the PARENTS' family. For a real trio the two coincide (the original
pipeline's LOO, `03_panel/apply_pon_loo.sb`); for a synthetic trio both the child's real parents (who carry the
"positive" allele) and the surrogate parents are excluded, so a positive and a negative row see the same kind of panel
and the feature cannot encode which trio type a row came from. `gnomad_af` is a site property and needs no LOO;
`sib_shared` is defined only in the two quads and is 0 elsewhere (a flag, P5). Annotation is one cohort-wide job over
the union of candidate sites, written as `annot/<child>.<class>.annot.tsv` and merged by the feature extractor.

### P27 — External-truth evaluation: the same harness on rows with known truth (M4, 2026-09-13)
Synthetic labels answer "does the model separate inherited-looking events from the raw candidate pool"; they saturate
for small variants and they cannot score the rescue branch of P15 (P22 caveat). The external-truth arm therefore reuses
the harness on rows whose truth is known by other means, with the SAME arms and the SAME scoring code:
(1) **Spike-ins** (`sim/spike.py`): the planted germline (G) and inherited-missed (IM) rows of every child, all classes,
as positives (G) and as labelled negatives (IM), against the child's real raw candidates as the negative pool. Each
child's rows are scored by the fold model that held its family out (seed 0), never by a model that saw the family;
the frozen all-family model is reported separately and marked as such. Mosaic spike-ins (CM/PM) are reported as a
sensitivity curve, not as positives (P10). (2) **WES-confirmed exonic small variants** (R10): candidates whose child
genotype is heterozygous and both parents hom-ref in SPARK iWES v3 DeepVariant, as positives, and candidates whose
child is hom-ref in WES as negatives, exonic rows only; added when the WES extraction step exists. (3) **GIAB** as the
reproducibility anchor once the trio is run (P16). Reported per class: ROC/PR-AUC of RF, RF+P (demotion **and**
rescue, allowed here because real trios have transmitted haplotypes), the heuristic arms including H2/H3 (population
filters are legitimate on these labels), and recall at the τ operating point. The spike-in arm is the only TR
external truth and is said so. *First result (seed 0, 2026-09-13):* RF 0.986 / 0.988 / 0.992 (SNV/indel / SV / TR) rising to 0.998 / 0.999 / 0.996 with the P15 layer including rescue; the slivar-type heuristic arms cannot be evaluated on spike-ins (no caller genotype on a planted candidate) — that comparison belongs to the WES-confirmed exonic set. *WES-confirmed set (58 / 2,926):* RF 0.930 vs slivar 0.880 ROC-AUC; slivar's own operating point TPR 0.64 at FPR 0.023; the P15 decision at τ_q 0.997 recovers 41 % vs the original set's 59 %; none of 1,864 WES-inherited candidates is called. *v4 (2026-09-14, five-seed models on the re-reviewed tables):* WES RF 0.943 vs slivar 0.880, PR-AUC 0.585 vs 0.543, 28 / 58 recovered by the full decision, still 0 / 1,864 inherited; spike-ins TR recall 0.99 (PR 0.91), SV 0.63 (0.45), SNV/indel 0 (planted small variants carry no caller block; the model's missing-value direction ranks them low — the rescue arm lifts them to ROC 0.998). Caveat recorded: the spike-in arm measures the phase layer and the read-level block, not the caller block, for small variants. *Truth-set audit (2026-09-14):* the 58 WES "positives" are our exonic candidates with de-novo-consistent iWES trio genotypes, not a curated DNM list; 6 carry gnomAD AF 0.02-0.11 or recur in 2-14 cohort families and 2 are hom-alt in the child's WES — ~50 are credible. The labelling rule is tightened to child 0/1, and both counts are reported. The faithful comparator is the original `denovo_tiered` set (recall 0.59, precision 0.94 on these rows), not the harness's re-implemented slivar arm (0.64 / 0.36), which is retained only as a scorer (P25). Planted candidates also carry no caller features, so on spike-ins the full small-variant model is handicapped (recall of planted SNV/indel DNMs at τ_q 0.999 = 0 despite AUC 0.986) while the phase-driven TR model recovers 0.89; the fair spike-in arm for small variants is the phase-only / read-level model, saved per fold for that purpose.

## 3. SynthDNM one-pager: what the code does, and what it implies for phase features

**Construction.** `swap_pedigree.py` shuffles complete families, pairs them, and writes a PED in which family A's parents get family B's offspring and vice versa. `extract_dnm_features.py` extracts FORMAT-level trio features at sites that look de novo *under the swapped pedigree* (child het, surrogate parents hom-ref; an `AC=2` condition appears in the extractor) → `truth=1`; and at putative DNM sites under the *real* pedigree → `truth=0`. `preprocess_features.py` derives `child_AR/min_AR/max_AR` (ref/(alt+1)), min/max over parents of `GQ, DP, PL0–2`, `child_AB`, `indel_flag`, sex-aware `haploid_flag` (PSAM + PAR BED), and samples `--sample_n` rows. `train.py` fits XGBoost (1000 trees, depth 6, lr 0.1, early stopping) on a stratified row-level split; `classify.py` emits `synthdnm_prob`. Published: ~96 % recall of denovo-db SSC DNMs.

**Implications.**
1. Positives use a real child and real surrogate parents: any feature that is a function of (child) or (a parent on its own, haplotypes unlabelled) exists for positives. Anything needing the parent–child relationship does not → `rf_safe: false`.
2. Pairing is an exchange → folds must contain whole pairs (P12). The current code has no grouping.
3. Negatives inherit the caller's label noise; on HiFi this is tolerable only for the raw set (0.2, P13).
4. Positives are inherited het variants at ~50 % VAF, clonal on one haplotype; mosaics are out of distribution (P10, P15).
5. The `universal` set is FORMAT-only and fully available in the GLnexus BCF — the natural baseline and the first 21 rows of `features.yaml`. `gatk`/`ssc` INFO features do not exist here.
